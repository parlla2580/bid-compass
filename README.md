# 입찰나침반

업종과 지역만 넣으면, 실제로 참여할 수 있는 공공조달 공고를 이유와 함께 골라 주는 무료 입찰정보 서비스입니다.
현재는 기획서 v2의 Phase 1 작업 순서 1번(7개 화면 클릭커블 프로토타입, 목데이터) 상태입니다.

## 실행

```bash
npm install
npm run dev     # http://localhost:3000 → /start 로 이동
npm run build   # 운영 빌드 확인
```

## 화면 (기획서 v2 6장)

| 화면 | 경로 | 내용 |
|---|---|---|
| S1 간편 시작 / 로그인 | `/start`, `/login` | 업종·지역 2개 입력 → 추천으로 바로 이동 |
| S2 대시보드 | `/` | 신규·참여 가능·저장 마감임박 요약, 참여 가능 상위 5건, 프로필 보완 배너 |
| S3 공고 리스트 | `/bids` | 커버리지 안내, 다중 필터, 판정 배지, 무한 스크롤 |
| S4 공고 상세 | `/bids/[id]` | 공고 해설 카드, 판정 사유와 인라인 입력, 용어 툴팁 |
| S5 추천 공고 | `/recommend` | 참여 가능/확인 필요 탭, 불가 공고 토글, 관련도·마감임박 정렬 |
| S6 적격심사 도구 | `/calculator` | 투찰금액 계산기(공고값 대조, 공사 98% 체크), 점수 계산기(기준점 수정) |
| S7 마이페이지 | `/mypage` | 기업 정보·매칭 선호도 수정, 저장한 공고 D-day |

## 구조

- `lib/data.ts` — 목데이터 공고 16건과 프로필 타입 (나라장터 API 연동 시 교체)
- `lib/judge.ts` — 참여 가능 판정(5.1), 관련도 정렬, 공고 해설(5.2)
- `lib/terms.ts` — 용어 툴팁 사전 (공개 전 문구 검수 필요)
- `lib/store.tsx` — 프로필·계정·저장 공고 상태 (브라우저 저장, Supabase 연동 시 교체)
- `app/calculator/rules.ts` — 계산 규칙과 예시값(5.3, 5.4)
- `prototype/` — 최초 HTML 프로토타입 (v1, 참고용)

## Phase 1 작업 순서 (기획서 9장)

1. 7개 화면 클릭커블 프로토타입 — 완료
2. Supabase 스키마 생성
3. 입찰공고정보서비스 API 수집 배치 + 공고 조건 정규화
4. 판정 엔진과 추천 정렬 (현재 `lib/judge.ts`를 서버로 이전)
5. 공고 해설 카드와 용어 툴팁 사전
6. 적격심사 도구
7. 간편 시작 → 추천 → 상세 흐름 점검, 아하 지표 이벤트 로깅
